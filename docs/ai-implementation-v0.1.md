# 智能围裙 V0.1｜AI 实现方案（周三技术汇报）

版本：0.1.0 · 日期：2026-10-27 · 对应[最终实施基线](implementation-plan-v0.1.md)。

**当前交付策略：真实实现教师编辑、审核、保存和版本规则；所有 AI、围裙通信与课堂采集采用明确标识的模拟服务。** 下面的候选技术是后续验证方向，不代表已接入、账号可用或能力已实测；不承诺 API、价格、时延或硬件协议。

## 1. 实现分工

AI 负责提出内容候选，程序负责结构校验、引用检查、内容保护与版本控制，教师负责取舍和最终批准。真实 AI 后续通过服务端代理接入，密钥不进入浏览器；首次实验仍只使用虚构数据。

| 功能 | 输入 | 模型职责 | 程序职责 | 输出格式 | 候选技术 | 难点与验证路径 |
|---|---|---|---|---|---|---|
| 教学目标推荐 | 虚构档案、教师需求、限制、带来源的目标模板 | 提出可观察目标及理由；信息不足时标记缺失 | P0 用规则筛选模板；保留来源，教师采纳后才写入目标 | `GoalSuggestion[]`：目标、理由、观察方式、来源 ID、待确认项 | P0 规则/模板；后续受限文本生成配合审核目标库 | 目标不等于专业处方；检查输入对应关系、观察方式及来源，由教师评价可用性 |
| 教案逐步生成 | 目标、限制、备注、已确认步骤、当前步骤 ID、请求和版本信息 | 只建议当前步骤的引导语、互动、观察点 | 校验结构与写入范围；呈现候选；采纳时复核版本、锁定及约束 | `StepSuggestion`：步骤 ID、内容、依赖版本、来源 | P0 上下文模板；后续可评估支持结构化输出的文本模型 | 连贯性、越界和迟到结果；用编辑后返回、切换活动、取消重试与错误输出验证保护规则 |
| 一键补全 | 上述上下文及明确的空白步骤 ID 列表 | 仅生成指定空白步骤的候选 | 先确定允许范围；返回和采纳时重新检查空白状态；逐项审核，不覆盖教师内容 | `StepSuggestion[]`：每条绑定稳定步骤 ID | P0 批量模板；后续批量或逐步文本生成，按实测选择 | 部分失败、重复请求、生成中被教师填写；测试保留草稿、锁定内容、重复采纳无副作用 |
| 故事生成 | 已审核目标与步骤、兴趣、长度/用语要求、限制 | 生成服务于练习目标的角色与分段故事 | 检查段落与步骤引用；候选审核、编辑保存；故事变化后提示反馈映射复核 | `StorySuggestion`：角色、段落 ID、步骤 ID、文本、注意项 | P0《小兔的水果野餐》模板；后续文本生成 | 故事有趣但偏离目标、段落改后映射失效；按每个表达机会检查引导和可观察行为 |
| 图像素材 | 教师确认的角色、段落与画面需求 | 后续生成画面候选，保留角色描述 | P0 返回本地演示素材；后续管理任务状态、素材来源、审核与本地引用 | `ImageCandidate`：素材 ID、段落 ID、资源引用、来源、审核状态 | P0 自制静态 SVG；后续可替换图像生成服务，供应商未定 | 角色一致性、适龄内容、权利与文件格式；先用同一故事少量画面人工审核，再验证替换不破坏引用 |
| 语音素材 | 教师确认文本、分段与语音偏好、限制 | 后续将确认文本合成为语音候选 | P0 返回本地短音频；控制播放/暂停、文字对应和审核；禁用声音时阻止配置 | `AudioCandidate`：素材 ID、文本、段落 ID、资源引用、来源、审核状态 | P0 本地短音频；后续可替换 TTS 服务，供应商未定 | 发音、节奏、文件兼容及播放可控；逐句听审，检查暂停与禁声限制，不编造设备音量阈值 |
| 教学复盘与证据引用 | 不可变教案快照、课堂事件、教师观察；包含来源与稳定证据 ID | 基于已给证据写事实摘要、缺失信息、反思问题，明确区分建议 | 程序汇总事实、验证引用存在且属于该课堂、展示原始证据；教师审核后才能追加档案 | `ReviewSuggestion`：事实条目及 `evidenceRefs`、缺失信息、反思问题、建议；无证据则明确说明 | P0 规则汇总/模板；后续带受限证据上下文的文本生成 | 引用真实存在仍可能不支持结论；程序检查引用归属，教师核对语义。注入缺失/无关证据，检查拒绝补造及不输出诊断 |

输出名为内部数据约定，不是任何厂商 API 字段。边界结构由 TypeScript 类型和运行时校验共同约束，模型输出符合格式也不代表教学内容正确。

## 2. 同一套输入输出保护

```text
教师提供/确认上下文
  → 程序限定本次请求范围并记录版本
  → 模拟服务（后续可替换真实模型）
  → 结构、范围、版本与引用检查
  → 待审核候选
  → 教师采纳/编辑/拒绝
  → 保存草稿 → 确认锁定 → 最终批准快照
```

每次文本请求携带 `requestId`、`lessonPlanId`、`revision`、`contextVersion` 与允许的目标 ID；结果携带同一关联信息。服务只能产生候选，不能直接写档案、锁定步骤、批准教案或发送设备指令。媒体候选同样关联请求、段落及版本，过期结果不能自动替换已审核素材。

围裙配置以程序规则匹配模拟能力目录，AI 至多提出映射建议。模拟传输输入为批准快照，结果记录尝试 ID、快照 ID、成功/失败与 `simulated` 来源；不定义任何尚未取得的物理通信协议。

## 3. 最小验证与汇报证据

| 层级 | 验证内容 | 可以说明什么 |
|---|---|---|
| 程序规则 | 锁定、补全保护、候选审核、过期拒绝、证据归属、保存与历史快照测试 | 教师内容和历史数据受到程序保护 |
| 模拟闭环 | 用唯一虚构案例演示生成、修改、批准、模拟传输、模拟课堂、复盘审核；包括失败重试 | 界面与业务流程可运行；不能证明真实模型、设备或教学效果 |
| 后续真实 AI 实验 | 同一虚构案例输入，比较输出结构、约束遵守、教师修改量、内容可用性、实际耗时与账单 | 才能形成服务选用与成本判断；当前未执行 |
| 真实教师/硬件场景 | 专业审核样例；取得设备协议与事件样例后联调；核对真实课堂证据 | 当前未验证，不在 P0 演示结果中宣称 |

规则与异常验证可使用同一案例的输入变体，不新增儿童示例。事实引用逐条可追溯至事件或教师观察；模拟事件即使引用完整，也只能支持“模拟流程中的观察”，不能转成真实儿童能力结论。

## 4. 本轮状态与下一步

已完成方案与职责边界文档，尚无应用或模型实验结果。实现顺序固定为工程与数据 → AI备课 → 故事与模拟围裙 → 审核、模拟传输与复盘 → 验证演练。网页验收状态与结果统一维护在实施基线中。

真实服务接入前再核实候选服务的官方接口、当前型号、账号/地域权限、数据条件、授权、实测费用和媒体格式；硬件接入前取得设备能力与协议。当前不需要为这些未知项重新开展选型讨论。
