## 1. 已确认范围与交付

交付一个本地可运行、可编辑、可保存的教师网页原型，以及独立的简明 AI 实现方案。完整走通：选择虚构儿童 → 创建活动 → AI备课 → 故事与围裙 → 审核与模拟传输 → 创建模拟课堂记录 → 教学记录与复盘。

| 真实实现 | 明确模拟 | 后续范围 |
|---|---|---|
| 导航、编辑、教师审核、步骤锁定、候选采纳、撤销、保存恢复、版本快照、历史引用 | AI 推荐与生成、围裙连接和通信、课堂采集、复盘草稿 | 真实 AI、后端与账户、真实儿童资料、硬件联调、专业评估、视频/EEG/fNIRS |

P0 支持一个儿童案例、多份活动草稿及同一教案的连续版本；不建设完整儿童档案管理系统。专业评估仅保留明确标为“后续功能”的说明入口，不提供评分、诊断或疗效图表。课中不新增持续操作的控制台。

## 2. 页面与操作结构

一级导航固定为：**教学工作台、儿童档案、教学记录**。

| 页面/工作区 | 内容与入口 |
|---|---|
| 教学工作台 | 新建活动、继续草稿、查看近期活动；由此进入课程工作区 |
| 儿童档案 | 一个虚构儿童的背景、偏好、沟通方式、限制与已审核观察；仅开放必要字段编辑 |
| 课程工作区（非一级导航） | **AI备课 → 故事与围裙 → 审核与模拟传输** |
| 教学记录 | 历次课堂、当时教案快照、事件证据；从单条记录进入课后复盘 |

保留原 HashRouter 路径策略：`/#/`、`/#/children/:childId`、`/#/activities/:activityId?stage=planning`、`/#/records`、`/#/sessions/:sessionId`；课程阶段使用 `planning/story/review`。路径仅负责定位，所有页面共享统一数据。

AI备课内组织“目标与限制 + 教学步骤”，不再将它们拆成顶部两个阶段。三栏分别为教学步骤列表、当前步骤编辑与候选区、目标/儿童限制/教师备注及检查结果。左栏教学步骤与顶部课程阶段使用不同名称。

每个阶段保留内容、保存状态、下一步和阻塞原因。审核问题直接定位到对应字段；允许返回修改。生成失败可重试或手工编辑；模拟传输失败不清空教案。

## 3. 工程基线与统一数据

固定采用 React + TypeScript + Vite、Context + useReducer、HashRouter、CSS Variables + CSS Modules；沿用 zod 边界校验、TypeScript/ESLint、Vitest/Testing Library/Playwright 的验证方案。实施时锁定依赖版本和 lockfile，不在本轮安装依赖。

目录沿用：`src/app`、`features`、`components`、`domain`、`services`、`storage`、`fixtures`、`styles` 和 `tests`。页面负责呈现，业务保护集中在 `domain`，模拟服务集中在 `services`。P0 不引入后端、AI SDK、硬件 SDK 或动画库。

| 模型 | 必要关联与内容 |
|---|---|
| `ChildProfile` | 稳定 ID、版本、虚构标识、背景、限制、审核观察 |
| `TeachingGoal` | ID、可观察目标、记录方式、教师要求与来源 |
| `LessonPlan` | 稳定 ID、儿童 ID、上下文快照及版本、目标、步骤、故事、反馈、当前修订号 |
| `ActivityStep` | 稳定 ID、顺序、引导语、互动、观察点、来源、内容版本及确认状态 |
| `Story` / `FeedbackMapping` | 稳定段落 ID、步骤 ID、素材引用、触发说明、模拟能力 ID |
| `ApprovedPlanSnapshot` | 唯一快照 ID、教案 ID、修订号、完整内容副本、审核时间、模拟来源信息 |
| `TransferAttempt` | 唯一尝试 ID、快照 ID、模拟标识、状态、错误、时间 |
| `ClassSession` | 稳定 ID、快照 ID、事件 ID、来源、观察与教师备注 |
| `ReviewDraft` | 课堂 ID、修订号、证据引用、教师修改、审核状态、拟追加观察 |

所有引用使用稳定 ID，不使用标题或数组下标。儿童档案更新不静默更新已有活动；教师主动更新上下文后，相关内容重新复核。

### 教师控制与异步保护

- 步骤状态为“空白、草稿、已确认”，另带“需复核”标记；解除确认后才可编辑已确认步骤。
- AI 只返回候选，结构及范围校验通过后供教师采纳。候选生成、预览均不修改正文。
- 一键补全只请求空白步骤，也先形成候选；采纳时再次检查步骤仍为空白。教师草稿、已确认内容和锁定内容一律保留。
- 每次请求绑定 `requestId`、教案 ID、修订号、上下文版本和目标步骤 ID；返回与采纳两次检查版本。编辑、取消、切换活动后的过期结果不得写入。
- 目标、限制、备注或上游内容改变时，保留原文并将依赖它的步骤、故事及反馈标为需复核，暂停最终批准。
- 结构化限制由程序校验；自由文本限制必须展示给教师复核，不宣称全部自动理解。
- 失败保留原文；阻止重复提交及重复采纳。每份活动保留最近 20 次内容操作撤销，撤销不改变已归档历史。

### 连续版本与不可变历史

同一 `LessonPlan.id` 可从已批准内容继续创建新修订，不必另建一份无关联教案。修订号递增；继续修订时复制为可编辑工作副本，旧批准快照不解除、不覆盖、不删除。

例如：教案 L 的 v1 批准为快照 S1，传输 T1 与课堂 C1 均引用 S1；教师继续修订得到 v2，重新复核批准为 S2。C1、T1 和其复盘仍引用 S1，后续传输与课堂可引用 S2。界面明确显示“当前草稿 v2 / 历史批准 v1”。

最终批准要求目标、步骤、故事及反馈完整，且没有未确认项、未处理候选或需复核项。批准时深复制并持久化完整快照；传输只读取快照。复盘编辑后重新待审核，追加档案观察须教师预览确认，并按课堂/审核版本防止重复追加。

### 保存与服务边界

P0 使用 `localStorage` 保存少量虚构文本，带 `schemaVersion`、修订号及更新时间；有效编辑自动保存，提供手动保存与成功/失败状态。刷新恢复活动和阶段，进行中的请求恢复为“已中断，可重试”。保存失败保留内存，不显示成功；损坏或不兼容数据不自动覆盖，提供原始数据下载及显式重置。重置需确认，先允许导出备份。媒体放本地静态资源，不写入文本存储。

保留 `GenerationService` 的 `recommendGoals/generateStep/completeSteps/generateStory/draftReview` 候选接口；媒体生成单独通过可替换素材服务承接。保留 `DeviceAdapter` 的 `connect/getCapabilities/transfer/disconnect`。P0 仅实现模拟适配器，模板读取当前上下文，不冒充通用生成能力。真实接口、设备参数及账号费用均未确认。

## 4. 已收敛的界面约定

主要参考本地 `frontend-ui-engineering`。采用专业、现代、克制的教师创作工具风格：暖中性背景、低饱和青蓝主色、清晰文字层级、三栏备课；以真实中文教学内容检查密度。

主操作为当前步骤的编辑、生成候选、采纳、确认；保存、锁定、模拟、待审核、失败状态跨页面一致。颜色之外同时提供状态文字，正文对比度按 4.5:1 验证；键盘焦点和表单标签完整。桌面优先，窄屏允许上下文栏折叠，保留编辑区域及必要操作。

仅使用帮助理解状态的轻量过渡，遵循减少动态效果设置。避免通用后台卡片堆叠、儿童游戏风格和复杂装饰。用户提供的 `huashu-design` 已核对；本轮是既有方案的文档收敛，不产出新视觉设计，不启动三方向选稿，也不把该 Skill 的 Babel 起手方式替代既定工程架构。

## 5. 唯一演示案例

**全部为虚构示例，未经专业验证，不代表正式教学处方。** 此说明在案例、教案及复盘中可见。

- 演示儿童 A：7 岁，喜欢动物故事，可使用简短词语表达。
- 故事：《小兔的水果野餐》。流程：故事引入 → 教师示范 → 引导表达 → 减少提示后尝试 → 回顾。
- 表达练习：三个故事机会中练习表达“我要苹果”；教师按“独立表达、提示后表达、未观察到”记录，不据此推断能力变化。
- 限制：不使用突然声音、闪烁或强制身体触碰，允许暂停。模拟反馈仅含图片预览和教师手动触发短语音，不代表硬件已支持。
- 课堂通过明确按钮“创建模拟课堂记录”生成，事件关联当前批准快照；事件与复盘持续显示模拟来源，不呈现为实测儿童表现。
