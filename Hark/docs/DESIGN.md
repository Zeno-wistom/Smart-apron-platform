# Hark 版本 · 设计规范与关键决策

## 1. 定位与视觉方向

安静、精致的教师创作工具。意象是“港湾”：暖纸色底（`--bg #f5f3ee`）、深海绿主色（`--primary #2e5a4f`），
以及**只属于 AI 的灯塔琥珀**（`--ai-*`）。

| 颜色 | 只用于 |
|---|---|
| 深海绿 | 主要操作、当前选中、已确认 |
| 灯塔琥珀 | AI 候选、AI 建议、AI 推断（教师内容永远不用琥珀） |
| 锈橙 | 需复核、限制冲突、阻止批准的问题 |
| 石板灰虚线 | 「模拟」标记、模拟设备、模拟记录 |

状态永远是**图标 + 文字**，不只靠颜色：空白（虚线圈）、草稿（铅笔）、已确认（锁）、需复核（三角）、AI 候选（琥珀点）。

## 2. 对齐系统（针对旧版问题专门设计）

- 品牌与侧栏导航共享同一个 28px「图标列」：品牌标志左缘 = 导航图标盒左缘（x=20），品牌名左缘 = 导航文字左缘（x=58）。
- 品牌行高度 = 顶栏高度 56px，侧栏第一条分隔线与顶栏底线对齐。
- 图标统一 16px（标签内 13px），`display:block` 避免基线偏移；按钮/导航文字使用 20px 行高的块级标签，与图标在 flex 中心线精确对齐。
- 控件高度三档：28 / 34 / 40px；圆角三档：6 / 8 / 12px；间距 4 的倍数。

## 3. 信息架构

一级导航：教学工作台 · 儿童档案 · 教学记录。教学活动内为四个阶段（顶部阶段条，标注课前 / 课中课后）：

1. **目标与环节**（AI 辅助备课）
2. **故事与围裙**（场景、互动节点、模拟反馈）
3. **审核与传输**（不可变版本、模拟连接与回执）
4. **课堂与复盘**（模拟课堂、复盘审核、写入档案）

URL 记录阶段与焦点（如 `#/activities/:id/plan?focus=step-xxx`），刷新、返回、从审核问题跳转都能回到同一编辑位置。

## 4. AI 备课工作区

三栏：**教案大纲** | **当前编辑** | **本课依据**。

- 当前编辑：编辑区顶部固定写「正在编辑 · 第 2 / 5 环节 · 示范」；大纲中当前项有白底、描边与左侧主色指示条；切换时编辑区有一次轻微闪现。
- AI 建议紧贴字段：候选卡就在该环节字段正下方，逐字段显示，被替换的字段标「将替换」；不会出现在页面另一侧。
- 目标与限制随时可见：右栏在编辑环节时固定展示目标、限制、备注；编辑目标时改为展示儿童档案要点 —— 同一信息不在两处重复。
- 一键补全影响可见：左栏琥珀卡片在点击前说明「为 N 个空白环节生成候选，保留你的 X 个草稿、Y 个已确认，候选需逐个采纳」。
- 长页面的下一步：编辑区底部操作条吸附在视口底部（上一项 / 确认，前往下一项 / 下一项）；所有环节完成后大纲出现「下一步：故事与围裙」。
- 返回修改不迷失：已确认环节只读并提示「解除确认以修改」，确认后自动跳到下一个待处理项。

## 5. 业务规则（在 `src/domain/reducer.ts` 集中实现，有单元测试）

- 环节状态：空白 → 草稿 → 已确认（锁定），另有「需复核」标记。已确认内容拒绝任何编辑与 AI 写入。
- AI 只产生候选（`candidate`），采纳前正文不变；采纳后成为草稿，仍需教师确认。
- 每次请求记录目标修订号与环节修订号；结果返回时若任一已变化则拒绝写入并提示原因（旧异步结果不能覆盖新修改）。
- 一键补全只请求发起时为空白的环节；返回或采纳时若教师已写草稿，一律不覆盖。
- 修改目标或限制：保留原文，将已有环节与故事标为需复核，阻止批准；教师可「内容仍适用」或修改后确认。
- 批准：无阻塞问题时深拷贝为不可变 `PlanVersion`（含校验码）；之后只能「基于 vN 继续修订」，旧版本、传输、课堂与复盘始终引用原版本。
- 课堂记录必须基于已成功（模拟）传输的版本；复盘只能写入空白复盘，不覆盖教师编辑；必须填写教师总结才能完成审核；审核后需再次确认才写入档案，且每次课堂只写入一次。

## 6. 模拟边界

模拟 AI（`src/services/mockAi.ts`）读取真实编辑的上下文：儿童档案（沟通方式、偏好、感官限制）、目标文本中的目标行为（轮流 / 指认 / 回顾 / 请求 / 自定义）、限制、教师备注、上一环节标题、环节角色；「换一个」使用不同写法。
围裙反馈只是一份“教学意图”目录（如“轮流卡图示”“教师预录短语”），仅含定性的「教师触发 / 自动」「是否突然」用于限制检查，**不包含任何模块编号、传感器、协议或刺激参数**。
