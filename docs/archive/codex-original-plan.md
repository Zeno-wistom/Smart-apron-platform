## B. 产品与页面架构

### 1. 四个主要入口，备课内部连续完成

不将六个候选界面机械拆成六个独立页面。

| 主要入口 | 页面职责 | 页面内组织 |
|---|---|---|
| 教学工作台 | 新建活动、继续草稿、查看近期记录 | 活动列表及明确的下一步操作 |
| 儿童档案 | 查看当前儿童的教学相关背景 | 偏好、沟通方式、限制、审核后的观察记录；P0 只开放关键字段编辑 |
| 备课工作台 | 从目标到模拟传输的完整准备过程 | 四阶段：目标与限制 → 教学环节 → 故事与反馈 → 审核与传输 |
| 教学记录 | 查看一次课堂及审核复盘 | 教案快照、事件时间线、教师备注、复盘草稿、档案更新预览 |

建议使用 HashRouter，即把页面路径放在网址 `#` 后，降低本地演示时刷新和路径配置的复杂度：

```text
/#/                         教学工作台
/#/children/:childId         儿童档案
/#/activities/:activityId    备课工作台，阶段放在查询参数中
/#/sessions/:sessionId       教学记录与复盘
```

页面路径只负责导航；档案、活动和课堂数据共享同一数据源，不能各页保存互不关联的副本。

### 2. 教师的主要路径

```text
教学工作台
  → 选择虚构儿童，创建活动
  → 确定目标与限制
  → 逐步生成、编辑、确认教学环节
  → 补全空白环节并审核
  → 编辑故事，配置模拟反馈
  → 审核教案并模拟传输
  → 明确点击“创建模拟课堂记录”
  → 查看事件、审核复盘
  → 预览并确认追加档案观察
```

课中不新增需要持续点击的控制台。首版用明确触发的模拟课堂记录说明课后流程。

### 3. AI 备课工作台布局

```text
顶部：活动名称｜儿童｜当前阶段｜保存状态｜模拟模式

┌──────────────┬────────────────────────┬──────────────────┐
│ 教学步骤列表 │ 当前步骤编辑区         │ 本次教学上下文   │
│              │                        │                  │
│ 引入         │ 名称、目的、教师引导语 │ 教学目标         │
│ 示范         │ 互动方式、观察点       │ 儿童限制         │
│ 引导练习     │                        │ 教师备注         │
│ 独立尝试     │ AI 建议及采纳操作      │ 约束检查结果     │
│ 回顾         │                        │                  │
│              │ 撤销｜生成建议｜确认   │                  │
└──────────────┴────────────────────────┴──────────────────┘

底部：待处理事项｜上一步｜一键补全空白环节｜下一阶段
```

左侧显示的是**教学步骤**；顶部显示的是**备课阶段**，两者不能混用。

具体交互：

- AI 建议显示在当前步骤旁，教师选择采纳后才进入正文。
- “确认并锁定”固定当前步骤版本；教师必须主动解除确认才能编辑。
- 一键补全默认只填空白步骤，保留已编辑草稿和已确认内容。
- 返回前一阶段保留所有内容，不重新初始化。
- 修改目标或限制后，相关内容标记“需复核”，保留原文，暂停最终确认。
- 审核页的问题直接链接回对应字段，避免教师重新寻找。

### 4. 抽屉、弹窗及后续入口

- **抽屉**：备课时快速查看儿童档案、查看建议差异。
- **弹窗**：解除确认、重置演示数据、确认追加档案观察。
- **行内提示**：字段问题、保存失败、生成失败及重试。
- **后续入口**：专业评估显示简短说明及所缺条件；视频、EEG、fNIRS 不展示虚构图表或可用设备。
- **演示设置**：次要位置提供“下一次生成失败”“下一次传输失败”，用于稳定演练异常流程。

### 5. 最小演示案例

以下全部为虚构教学演示，不代表经过验证的干预方案。

- 儿童：演示儿童 A，7岁，喜欢动物故事，可使用简短词语表达。
- 本次目标：在故事中的三个机会里，练习主动表达“我要苹果”；教师记录独立表达、提示后表达或未观察到。
- 限制：不使用突然声音和闪烁效果，不要求触碰教师身体，允许暂停。
- 故事：《小兔的水果野餐》。
- 教学步骤：故事引入 → 教师示范 → 引导表达 → 减少提示后尝试 → 回顾。
- 模拟反馈：图片展示、教师手动触发短语音。它们是软件演示能力，不代表围裙已有接口。

| 环节 | 用户操作及界面变化 | 数据变化 | 真实与模拟边界 |
|---|---|---|---|
| 选择儿童 | 查看档案后创建活动 | 新建活动并引用儿童 ID、档案版本 | 真实操作，虚构资料 |
| 确定目标 | 采纳推荐、编辑表达要求及限制 | 保存目标、限制及备注 | 推荐来自模板，编辑真实 |
| 生成环节 | 请求生成“故事引入” | 产生待采纳建议 | 模拟生成 |
| 编辑确认 | 修改教师引导语，确认并锁定 | 保存教师内容和确认版本 | 真实状态规则 |
| 一键补全 | 填入其余空白步骤，逐项审核 | 仅添加空白步骤草稿 | 模拟内容，真实合并规则 |
| 生成故事 | 查看故事段落并编辑 | 段落绑定教学步骤 ID | 模拟生成，编辑真实 |
| 匹配反馈 | 将图片、短语音绑定故事节点 | 保存反馈映射 | 本地预览真实，硬件能力模拟 |
| 审核教案 | 检查遗漏及限制，确认当前版本 | 形成不可变教案快照 | 真实版本管理 |
| 模拟传输 | 连接模拟设备并发送 | 保存快照 ID、传输状态 | 不发生硬件通信 |
| 查看课堂 | 点击创建模拟记录 | 按快照生成事件和三个演示观察项 | 全部标记模拟来源 |
| 审核复盘 | 编辑、批准复盘及拟追加观察 | 保存审核版本，按选择追加档案 | 审核真实，观察依据为模拟数据 |

## D. 工程技术方案

### 1. 技术栈与依赖

**采用 React + TypeScript + Vite，适合当前本地交互原型。**当前 Node 版本满足 Vite 文档列出的基础要求；后续初始化仍以实际模板要求为准。[Vite 官方文档](https://vite.dev/guide/)

最小依赖：

| 类别 | 选择 |
|---|---|
| 界面 | `react`、`react-dom` |
| 路由 | `react-router-dom` |
| 边界数据校验 | `zod`，检查存储及生成结果是否符合预期结构 |
| 样式 | CSS Variables + CSS Modules |
| 状态 | React `useReducer` + Context |
| 验证 | TypeScript、ESLint、Vitest、Testing Library、Playwright |

Reducer 是集中管理“编辑、确认、撤销”等状态变化的函数；Context 让相关页面共享状态。这种组合已有官方使用说明，当前不需要再引入独立全局状态库。[React 官方文档](https://react.dev/learn/scaling-up-with-reducer-and-context)

P0 不增加后端、账号系统、数据库服务、AI SDK、硬件 SDK 或动画库。进入实施阶段再确定稳定版本并提交 lockfile，本轮不安装。

### 2. 最小目录结构

以下为建议结构，尚未创建：

```text
src/
  app/          路由、公共布局、应用入口
  features/     dashboard、children、planning、sessions
  components/   按钮、表单、抽屉、状态提示等公共组件
  domain/       数据类型、状态规则、校验、版本处理
  services/     生成服务、设备接口及模拟实现
  storage/      本地存储与恢复
  fixtures/     虚构档案、教学模板、模拟事件
  styles/       颜色、字体、间距及全局样式
tests/          关键业务规则与浏览器闭环测试
```

页面负责展示与操作，业务规则集中在 `domain`，模拟逻辑不散落在组件中。

### 3. 核心数据模型

统一使用稳定 ID 关联数据，不通过标题或数组位置匹配。

| 模型 | 最低必要内容 |
|---|---|
| `ChildProfile` | 虚构标识、昵称、年龄、沟通方式、偏好、限制、观察记录、版本 |
| `TeachingGoal` | 目标描述、观察方式、教师要求、来源 |
| `LessonPlan` | 儿童引用、备课上下文、目标、限制、备注、步骤、故事、反馈、修订号 |
| `ActivityStep` | 稳定 ID、顺序、目的、教师引导语、互动方式、观察点、来源、确认状态 |
| `Story` | 角色、段落、段落与步骤的关联 |
| `FeedbackMapping` | 步骤/段落引用、触发说明、模拟能力及素材引用 |
| `ApprovedPlanSnapshot` | 教师确认时的完整内容、原教案 ID 和修订号 |
| `TransferAttempt` | 快照引用、模拟标识、状态、失败原因及时间 |
| `ClassSession` | 教案快照引用、数据来源、事件、教师观察 |
| `ReviewDraft` | 事实摘要、对应事件引用、教师修改、审核状态、拟追加档案内容 |

儿童档案后来更新，不静默改变已有活动的上下文；教师可主动更新上下文，随后重新复核。

### 4. 必须由程序保证的状态规则

**内容保护**

- 步骤采用“空白、草稿、已确认”状态，另有“需复核”标记。
- 已确认步骤禁止生成服务直接修改；教师解除确认后才能编辑。
- 一键补全只处理空白步骤。重新生成针对教师明确选择的未确认步骤，结果先作为建议呈现。
- AI 输出只能包含请求范围内的内容，不能修改儿童档案、目标、限制或其他步骤。
- 修改目标、限制或备注后，相关步骤、故事和反馈标记需复核；不删除原文。

**约束继承**

- 每次生成携带当前目标、限制、备注和已确认步骤。
- 结构化限制由规则校验，例如“禁止声音”时不可配置音频反馈。
- 自由文本备注完整继承，但不能宣称程序已理解所有含义，仍需教师检查。
- 约束不能仅靠提示词保护；锁定检查、输出范围检查必须在程序中执行。

**异步与撤销**

- 每次生成绑定请求 ID、教案修订号和上下文版本。
- 生成期间教师修改内容或离开活动，迟到结果不能覆盖新内容。
- 失败保留原文，允许重试或继续手工编辑。
- 每份活动保留最近20次内容操作的撤销记录；撤销不回滚已归档课堂或传输历史。

**审核与历史**

- 最终审核要求目标、步骤、故事和反馈完整，且无待复核项。
- 审核通过生成教案快照；传输和课堂都引用该快照。
- 后续修改教案产生新修订，需要重新审核、重新传输；旧课堂保持原样。
- 复盘重新编辑后回到待审核状态；追加档案时检查是否已追加，避免重复。

### 5. 保存与恢复

P0 使用 `localStorage`，即当前浏览器、当前网址下的本地存储，仅保存少量虚构文本数据。

- 保存数据包含 `schemaVersion`、修订号和更新时间。
- 有效编辑后自动保存，同时提供明确的保存状态和手动保存按钮。
- 刷新后恢复当前活动及备课阶段；进行中的生成和传输恢复为“已中断，可重试”。
- 保存失败显示“未保存”，保留内存内容，不伪报成功。
- 数据损坏或版本不兼容时，不静默覆盖；提供原始数据下载及重新载入演示数据的选择。
- 图片、音频使用本地静态资源，不把大文件塞入 `localStorage`。
- 演示固定使用同一浏览器和网址端口；不同来源的浏览器存储不自动互通。

正式系统再替换存储实现，加入账号、权限、备份及审核记录。`localStorage` 不作为真实儿童档案库。

### 6. 可替换的服务接口

生成接口返回**建议**，不返回可直接覆盖整个应用状态的对象：

```ts
interface GenerationService {
  recommendGoals(input: GoalContext): Promise<GoalSuggestion[]>;
  generateStep(input: StepRequest): Promise<StepSuggestion>;
  completeSteps(input: CompletionRequest): Promise<StepSuggestion[]>;
  generateStory(input: StoryRequest): Promise<StorySuggestion>;
  draftReview(input: ReviewRequest): Promise<ReviewSuggestion>;
}
```

所有生成输入包含必要上下文、请求 ID 和版本；结果经过结构校验和范围检查后，再交给教师采纳。

模拟实现使用模板、条件分支和少量延迟，真实读取当前字段。它能证明页面和状态流程，**不能证明对任意教学需求都有生成能力**。

设备接口采用：

```ts
interface DeviceAdapter {
  connect(): Promise<DeviceConnection>;
  getCapabilities(): Promise<DeviceCapabilities>;
  transfer(snapshot: ApprovedPlanSnapshot): Promise<TransferResult>;
  disconnect(): Promise<void>;
}
```

P0 只有 `MockDeviceAdapter`，模拟未连接、连接中、已连接、传输中、成功和失败。能力目录注明 `simulated`，不填写虚构通信协议、物理位置、音量阈值或刺激参数。

### 7. 后续接入原则

- 真实 AI 经后端转发，密钥不放在浏览器代码。
- 文本生成首先评估支持结构化输出的模型；结构化输出是按约定字段返回结果，不等于内容正确。[OpenAI 官方说明](https://developers.openai.com/api/docs/guides/structured-outputs)
- 首个虚构数据实验可选支持该能力的 OpenAI 文本模型；真实数据使用前，必须确认机构批准的供应商、地域、留存和费用条件。
- “不用于训练”不等于“不留存”；不能据此自行批准上传真实儿童数据。[OpenAI 数据控制说明](https://developers.openai.com/api/docs/guides/your-data)
- 正式生产型号、价格和账号可用性留到 P1 核实，不影响 P0。
- P0 无云端请求、统计追踪、真实儿童资料或外部字体依赖。

## E. AI 模块实现矩阵

下表中的“可验证”表示后续实施时能做的验证，本轮没有运行功能实验。

| 教学目标推荐 | 当前上下文、教师需求、目标模板 | P0规则筛选；P1文本模型辅助说明；输出目标、理由、可观察方式及来源 | 推荐不能冒充专业处方；用虚构案例检查是否符合输入 | 专业人员审核的目标库及选用标准 |
| 逐步生成教案 | 已选目标、限制、已确认步骤、当前环节 | 文本模型生成单步建议；程序控制写入范围；输出引导语、互动及观察点 | 检查连贯性、教师可操作性、锁定保护；P0模板验证流程 | 教案样例、教师评价标准、模型账号及费用 |
| 约束继承 | 结构化限制、教师备注及上下文版本 | **程序强制保护**；模型参考上下文；输出校验结果和待复核提示 | 自由文本不能完全自动验证；测试禁止声音及迟到结果 | 专业限制分类、允许范围和硬件能力 |
| 一键补全 | 未填步骤、上下文及已确认内容 | 程序决定允许填充的 ID，模型生成候选；输出按步骤关联的建议 | 测试仅填空白、失败保留原文、重复点击无重复步骤 | 稳定批量生成能力、质量和耗时实测 |

| 围裙反馈匹配 | 故事节点、教师选择、设备能力目录 | **规则匹配为主**，AI只提建议；输出节点—触发—反馈映射 | 验证禁用反馈不会被选中；P0用模拟能力目录 | 实际模块、触发方式、参数、协议及确认机制 |
| 教学事件记录 | 实际设备事件或教师观察 | **普通程序记录**；输出事件 ID、来源、时间及步骤引用 | P0事件由已确认快照生成，不能来自无关固定记录 | 真实事件样例、设备时钟、断连及同步规则 |
| 课后教学复盘 | 教案快照、事件、教师观察 | 程序汇总事实，文本模型写草稿；输出事实、证据引用、缺失信息及反思问题 | 验证每条事实有依据、缺失内容不补造；P0规则模板可验证审核流程 | 真实记录、报告样例、审核人及质量评测 |

### P0 验收清单

**业务规则测试**

- 一键补全保留已确认步骤及教师编辑草稿。
- 目标或限制修改后，相关内容需复核。
- 旧生成结果不能覆盖新编辑；取消、重试和重复点击不造成重复数据。
- 错误或越界的生成结果被拒绝，原文保留。
- 教案修改后，旧课堂和旧传输仍引用原快照。
- 未审核复盘不能追加档案；重复确认不会重复追加。

**浏览器验收**

- 从新活动开始，走完一次约5–8分钟完整演示。
- 真实修改引导语并确认，随后补全，检查内容保留。
- 生成失败后重试；传输失败后重试；重新进入草稿继续操作。
- 关键阶段刷新后恢复；模拟处理中刷新显示中断。
- 在1366×768和1440×900检查遮挡、滚动、长文本与主要按钮。
- 检查键盘焦点、弹窗、表单标签和减少动态效果。
- 页面无未处理控制台错误；断网后核心演示不依赖外部服务。
- 执行类型检查、业务测试和构建；最终检查实际构建产物。

验收记录分为：**程序规则通过、模拟流程通过、真实硬件/教师场景未验证**。前两类不能代替第三类。

进度紧张时先缩减装饰动画、素材数量及列表辅助功能；保留锁定保护、保存恢复、异常处理和完整闭环。
